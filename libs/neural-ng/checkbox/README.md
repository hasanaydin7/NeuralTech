# NeuralNg Checkbox

Checkbox Beta provides native, Signal-first binary and tri-state controls for Angular 22+.
The two value contracts are intentionally separate so every Angular Forms
adapter sees one stable model type.

## Import

```ts
import { NeuralCheckbox, NeuralTriStateCheckbox, type NeuralCheckboxChange, type NeuralTriStateCheckboxChange, type NeuralTriStateCheckboxValue } from '@neural-ng/core/checkbox';
```

## Binary checkbox

```html
<neural-checkbox [(checked)]="accepted" required (stateChange)="acceptedChanged($event)"> I accept the terms </neural-checkbox>
```

`NeuralCheckbox` implements `FormCheckboxControl`. Its `checked` model is
always `boolean`, which makes the same component compatible with Signal Forms,
Reactive Forms, and template-driven forms.

For collection-level “some selected” controls, set `[indeterminate]="true"`.
This is presentation and accessibility state (`aria-checked="mixed"`), not a
third model value: `checked` remains strictly boolean. Use
`NeuralTriStateCheckbox` when `null` is part of the application value.

```html
<neural-checkbox [formField]="form.accepted">Accept</neural-checkbox>
<neural-checkbox [formControl]="acceptedControl">Accept</neural-checkbox>
<neural-checkbox name="accepted" [(ngModel)]="accepted">Accept</neural-checkbox>
```

## Tri-state checkbox

```html
<neural-tri-state-checkbox [(value)]="permission"> Inherit permission </neural-tri-state-checkbox>
```

`NeuralTriStateCheckbox` implements
`FormValueControl<boolean | null>`. Interaction cycles
`false -> true -> null -> false`. `null` is rendered through the native
checkbox's `indeterminate` property and `aria-checked="mixed"`.

```html
<neural-tri-state-checkbox [formField]="form.permission"> Inherit permission </neural-tri-state-checkbox>
<neural-tri-state-checkbox [formControl]="permissionControl"> Inherit permission </neural-tri-state-checkbox>
<neural-tri-state-checkbox name="permission" [(ngModel)]="permission"> Inherit permission </neural-tri-state-checkbox>
```

Tri-state has no separate `indeterminate` model. Its `value` remains the single
authoritative source; the binary Checkbox input is only for collection-state
presentation.

## Migration from the combined alpha API

```html
<!-- Before -->
<neural-checkbox triState [(checked)]="permission"> Inherit permission </neural-checkbox>

<!-- After -->
<neural-tri-state-checkbox [(value)]="permission"> Inherit permission </neural-tri-state-checkbox>
```

Binary usages keep `neural-checkbox` and `[(checked)]` unchanged.

## Events

Binary Checkbox:

- `checkedChange` is generated by the `checked` model.
- `stateChange` emits `{ checked, previousChecked, nativeEvent }` for user
  actions.

Tri-state Checkbox:

- `valueChange` is generated by the `value` model.
- `stateChange` emits `{ value, previousValue, nativeEvent }` for user actions.

Programmatic form or model updates do not emit either semantic `stateChange`
event.

## Readonly and disabled

`disabled` removes the native control from interaction and focus. `readonly`
keeps it focusable, exposes `aria-readonly="true"`, and blocks mutation. Both
controls emit `touch` when the native input loses focus.

## Native behavior

Both components contain a real `<input type="checkbox">`. Label activation,
Space, focus, required, name, input value, constraint validation, and form
submission retain native behavior. Native HTML submission only submits checked
checkboxes; use the Angular model when `false` or `null` must be persisted.

## Styling

The default check and mixed marks are pure CSS, so neither component depends on
an icon package. Both share `--neural-checkbox-*` theme tokens.

`unstyled` removes visual classes while preserving the native input, structure,
state, and consumer classes. Use `checkboxClass`, `inputClass`, `labelClass`, or
typed `classes` slots.

Binary slots: `root`, `input`, `control`, `checkedControl`, and `label`.
Tri-state adds `mixedControl`.

## Field composition

Inside `neural-field`, both components inherit deterministic control ids,
descriptions, required, invalid, disabled, readonly, pending, fluid, and
unstyled state.

The generated ids use Angular's application id and deterministic counters. The
components contain no eager browser globals and are safe for SSR and hydration;
`focus()` only touches the native element when explicitly called in a browser.

## Compatibility aliases

`CheckboxComponent` and `TriStateCheckboxComponent` remain deprecated aliases.
New application and AI-generated code must use `NeuralCheckbox` and
`NeuralTriStateCheckbox`.

## Beta boundary

Checkbox Beta includes native binary and tri-state inputs, all three Angular
Forms adapters, Field composition, readonly and disabled semantics, required,
invalid and pending state, semantic user events, imperative focus/reset,
typed class slots, global/local unstyled behavior, theme tokens, SSR and
hydration safety. Group validation and business rules remain application or
Field responsibilities.
