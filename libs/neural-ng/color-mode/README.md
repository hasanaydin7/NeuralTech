# NeuralNg Color Mode

`@neural-ng/core/color-mode` is an optional, Signal-based light/dark/system
controller. It keeps color mode separate from the selected visual theme and
writes only the namespaced `data-neural-mode="light|dark"` attribute to the
document root.

Use `@neural-ng/core/appearance` instead when one controller should also own
primary palettes, surface palettes, direction, and their persisted settings.
Do not register both providers; `provideNeuralAppearance()` already configures
this color-mode service.

## Setup

```ts
import { ApplicationConfig } from '@angular/core';
import { provideNeuralColorMode } from '@neural-ng/core/color-mode';

export const appConfig: ApplicationConfig = {
  providers: [
    provideNeuralColorMode({
      defaultMode: 'system',
      storageKey: 'neural-color-mode',
    }),
  ],
};
```

The provider is optional when an application owns the attribute itself. It is
recommended when using `NeuralColorModeService`, because it initializes the
mode during application startup even if the service is not injected elsewhere.

## Signals and commands

```ts
import { Component, inject } from '@angular/core';
import { NeuralColorModeService } from '@neural-ng/core/color-mode';

@Component({
  selector: 'app-color-mode-picker',
  template: `
    <button type="button" (click)="modes.set('light')">Light</button>
    <button type="button" (click)="modes.set('dark')">Dark</button>
    <button type="button" (click)="modes.set('system')">System</button>
    <output>{{ modes.preference() }} / {{ modes.resolvedMode() }}</output>
  `,
})
export class ColorModePicker {
  readonly modes = inject(NeuralColorModeService);
}
```

| API            | Type                                    | Meaning                                |
| -------------- | --------------------------------------- | -------------------------------------- |
| `preference`   | `Signal<'light' \| 'dark' \| 'system'>` | User-facing preference                 |
| `resolvedMode` | `Signal<'light' \| 'dark'>`             | Concrete mode currently written to DOM |
| `isDark`       | `Signal<boolean>`                       | Convenience derived state              |
| `set(mode)`    | `void`                                  | Select and persist a preference        |
| `reset()`      | `void`                                  | Restore the configured default         |

`system` follows `(prefers-color-scheme: dark)` live. The DOM always receives a
concrete `light` or `dark` value so CSS frameworks can consume the same selector.
Valid stored preferences synchronize between browser tabs. Storage failures do
not prevent color switching. Set `storageKey: null` to disable persistence.

## Theme and mode are independent

```html
<html data-neural-mode="dark">
  <main data-neural-theme="neutral">...</main>
</html>
```

- `data-neural-theme` selects `neutral`, `glass`, `futuristic`, or another theme.
- `data-neural-mode` selects the resolved light/dark palette.
- NeuralNg does not add, remove, or inspect a generic `.dark` class.

The stable neutral stylesheet exposes semantic `--neural-color-*` tokens and
maps component tokens onto them. Component tokens remain independently
overridable.

## Tailwind CSS

NeuralNg has no Tailwind dependency. Tailwind CSS v4 consumers can opt into the
same namespaced attribute:

```css
@import 'tailwindcss';
@import '@neural-ng/core/themes/neutral.css';
@import '@neural-ng/core/themes/tailwind.css';

@custom-variant dark (
  &:where([data-neural-mode='dark'], [data-neural-mode='dark'] *)
);
```

The optional bridge maps the full NeuralNg primary and surface primitive
palettes into Tailwind v4's `--color-*` namespace. Classes such as
`bg-primary-50`, `hover:bg-primary-700`, `text-surface-950`, and
`dark:bg-surface-900` are then generated by Tailwind. The bridge contains no
runtime JavaScript and does not make Tailwind a NeuralNg dependency.

Applications may also keep their existing Tailwind strategy and mirror their
resolved mode onto `data-neural-mode`. The CSS token package does not require the
Angular service.

## Preventing the initial flash

SSR applications cannot know browser-only local storage or operating-system
preferences during the first server render. If persisted selection must be
applied before CSS paints, add a CSP-compatible inline bootstrap script in the
document head that resolves the same storage key and sets `data-neural-mode`.
The demo includes a minimal example. With a strict CSP, authorize that script by
hash or nonce according to the application's security policy.

## SSR behavior

The service does not read browser globals, storage, media queries, or mutate the
DOM on the server. Server-side `resolvedMode` deterministically falls back to
the configured explicit mode, or light when `defaultMode` is `system`.
